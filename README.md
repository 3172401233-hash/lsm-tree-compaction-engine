# lsm-tree-compaction-engine

Python LSM Tree 压缩规划与执行模型。针对"运行一周后低层文件暴涨、同一 key
残留多个旧版本、墓碑被过早物理删除导致旧值复活"的问题，本引擎把墓碑回收
与文件大小解耦：**只有确认更底层不存在该 key 的旧值时，墓碑才能被物理删除**。

## 模块结构

- `lsm/sstable.py` — SST 文件元数据（key 范围、世代、大小、墓碑集合）与落盘格式
- `lsm/version.py` — 版本 / VersionSet，压缩以 VersionEdit（增删文件映射）原子应用
- `lsm/compaction.py` — 压缩规划器（打分选层、范围扩展、祖父层重叠收集）与合并执行
- `lsm/manifest.py` — MANIFEST（版本编辑日志）与 WAL，崩溃恢复的依据
- `lsm/engine.py` — 读写路径、压缩调度、进行中任务跟踪、失败回滚、孤儿文件清理

## 可见性顺序

同一 key 可能存在于多处，读取按固定顺序短路，先命中者生效：

1. Memtable（最新写入）
2. L0 文件，按 file_id 从大到小（L0 文件允许互相重叠，新文件优先）
3. L1 … Ln，由浅到深（L1+ 层内文件互不重叠，层内按键序二分）

压缩维持该不变式：合并时同一 key 只保留 seq 最大的条目；被压缩文件通过
一次 MANIFEST 编辑原子地替换为输出文件，因此压缩前后任意 key 的可见值不变。
删除后重插同一个 key 依赖 seq 单调递增——新写入的 seq 永远大于旧墓碑。

## 墓碑物理删除规则

合并输出某个 key 的获胜条目是墓碑时：

- 若**输出层之下**（比 output_level 更深的所有层）没有任何文件的 key 范围
  覆盖该 key，则旧值不可能存在，墓碑连同旧值一起物理丢弃；
- 否则墓碑必须保留并随输出写回，等待将来与更深层旧值一起合并时再回收。

这正是原 bug 的根因：按文件大小决定丢墓碑，等价于在更底层仍持有旧值时
删除了删除标记，旧值于是在读取时"复活"。

## 压缩规划

- 打分：L0 按文件数 / `l0_compaction_trigger`，Li 按总大小 / 层容量
  （`level_size_base * multiplier^(i-1)`），分数 ≥ 1 的最高分层胜出，平分取浅层。
- 选文件：L0 从最老文件出发做重叠范围传递闭包（L0 必须整批合并）；Li 取最大文件。
- 祖父层收集：输出层中与输入范围重叠的所有文件一并参与合并。
- 三种任务：`merge`（重写合并）、`trivial_move`（单文件且下层无重叠时直接改级，
  零重写）、`delete_empty`（清理空文件）。
- 输出按 `max_file_size` 切分，避免产生超大文件。

## 写放大权衡

分层压缩的写放大约为 `O(层数 × 层容量倍数)`：每条数据在每一层平均被重写
`multiplier / 2` 量级次。调参方向：

- 增大 `level_size_multiplier`：层数减少、读放大降低，但单层合并更重、
  空间放大（新旧文件并存）更差；
- 增大 `l0_compaction_trigger`：L0 合并更少、写放大降低，但点查要看的
  L0 文件更多、读放大升高；
- 增大 `max_file_size`：输出文件更大、元数据更少，但单个合并任务更长、
  崩溃时浪费的已写输出更多；
- `trivial_move` 是写放大的主要优化：下层无重叠时只改元数据不重写数据。

引擎通过 `engine.stats` 暴露 `compaction_bytes_read/written`，
`written/read` 即实测写放大系数。

## 进行中写入与失败处理

- `begin_compaction` 把输入文件登记为进行中，规划器跳过这些文件，
  冲突的第二个压缩会被拒绝；flush 不受阻塞。
- 压缩输出先写临时文件再原子 rename；任何中途异常触发 `abort_compaction`，
  已写出的部分输出被删除，版本保持不变。
- 提交 = 一条 MANIFEST 编辑（删旧文件、加新文件）落盘并 fsync，
  之后旧输入文件才被删除。

## 崩溃恢复

1. 重放 MANIFEST（最近快照 + 后续编辑）得到版本状态；
2. 删除所有未被 MANIFEST 引用的 SST 文件——即崩溃时未提交压缩的孤儿输出；
3. 重放 WAL 恢复未 flush 的 Memtable；
4. 写入新快照，压缩 MANIFEST。

无论在输出写入中、提交前还是提交后崩溃，恢复结果都等于某个一致的历史版本。

## 测试

```
python -m unittest
```

覆盖：点查（跨层可见性）、范围扫描（墓碑过滤、多源合并）、删除后重插、
墓碑保留/丢弃规则、L0 重叠扩展、空文件、进行中压缩互斥、压缩失败回滚、
崩溃恢复（已提交 / 未提交 / WAL）、层数增长、规划与合并的确定性、写放大统计。
